# Technomantra Adaptive Cost Optimizer V4.11.6

This is the final cost-efficiency layer. It must reduce repeated context without reducing coding intelligence, correctness or source awareness.

## Non-negotiable intelligence contract
1. Accuracy, current source truth, developer instructions and architecture correctness always outrank token saving.
2. Never guess because context was compacted. Re-read the smallest exact source range when current evidence is genuinely missing.
3. Paid/manual model selection remains exact. Never switch paid models to save money. Eco routing remains separate and portal-controlled. Vision Routing remains separate.

## Adaptive context
1. Normal paid/manual work keeps the existing 48K active-token target; deep cross-file architecture may retain about 96K; visual build may retain about 64K; Eco keeps the existing 28K target. Cost saving must never reduce the evidence budget below the previously stable paid/Eco behavior.
2. When a target is crossed, use Cline's native context/file-read optimization and checkpoint/condense path before the next provider call. Preserve current goal, latest developer correction, architecture decisions, touched files, current diffs/errors and pending work.
3. Old environment snapshots, exact duplicate tool results and successful saved-file echoes are disposable once newer/current evidence exists.

## Tool evidence
1. An unchanged full file should normally be read once. A second unchanged full-file request must use targeted search/range evidence instead.
2. Never resend full file content after a successful edit.
3. Very large deterministic search/list/terminal/browser/MCP output may be compacted to head + tail with an explicit marker. If omitted middle detail becomes necessary, run one targeted query rather than restoring the entire old dump.
4. Source-code reads are not blindly truncated by the optimizer. Exact code needed for a safe edit must remain available or be refreshed by a targeted read.

## Cost-per-completed-task behavior
1. Prefer local project indexes, hashes, symbol/search caches and prior unchanged evidence before another model turn.
2. Exact duplicate in-flight requests, permanent errors and runtime guards are not retry opportunities.
3. 429/502/503/504 handling remains the V4.11.5 classified same-model retry policy.
4. Finish coherent work once verified; do not spend extra turns re-auditing unchanged files.
